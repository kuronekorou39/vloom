画面→カメラのデータ転送 — 関連研究・先行事例

Vloom の位置づけを確かめるための調査。2026-10-19 時点 (前回は 2026-07-02、QR 経路の頃)。
方針どおり第三者のソースコードは読まず、README・性能ドキュメント・論文・記事・ストアページの 公開情報だけを参照した。数値は各者の自己申告で、測定条件はそろっていない。

要点

  • 2026 年 7 月以降、同じ発想の OSS が相次いで出ている。 火付け役の Decimen は Tom's Hardware に取り上げられ (★6.9k)、謳い文句「no network, no pairing」が Vloom とほぼ同じ。
  • 公表値で Vloom より速いものがある。 Decimen 418 KB/s (49 型モニタ・60fps・最良 1 回の記録)、LIZARD 3.8 MB/s (未検証)。 「世界最速」は書けない。
  • 学術研究と比べると上。 市販スマホでリアルタイム受信した報告は、誤り訂正後で数百 kbps 止まり。 Vloom の 1.1〜1.7 Mbps (ファイルを最後まで転送した値) はそれを上回る。 ただし端末の世代差 (先行研究は 2013〜2016 年の端末) が大きい。
  • 設計が一番近いのは FOCUS (MobiSys 2016)。 グレースケール + Fountain 符号 + 断片ごとの誤り訂正。 「fountain 符号を初めて使った」「部分回収が新しい」とは言えない。
  • iPhone で受信できることは、もう前提になっている。 Decimen・RaptorQR・cimbar は、どれもブラウザで iPhone 受信に対応している。

技術の系統

見えるコードの高容量化

PixNet → COBRA → LightSync / RDCode → SoftLight / FOCUS → FareQR / RescQR。 多値化の手段は色・周波数領域 (OFDM)・色差。2016 年以降は主要会議での研究が減り、QR ストリームの改良が中心になった。

人の目に見えない埋め込み

InFrame++、ChromaCode、AirCode。120Hz 表示が前提で、誤り訂正後は約 120〜180 kbps。 見出しの raw 値 (777〜1069 kbps) と取り違えないこと。Vloom とは比べる相手が違う。

同期・ローリングシャッターの扱い

考え方は 3 つに分かれる。
  • 避ける: 表示 fps を撮影の半分にする (PixNet、COBRA)
  • 分ける: 混ざりを推定して分離する (LightSync、FareQR、RescQR)
  • 捨てる: 消失として扱う (InFrame++、SoftLight、Peng 2025)
Vloom は「捨てる」側。混ざったブロックは CRC で落とす。救済を試したが +0.6〜1.5% だった (experiments.md の 2026-10-06)。

誤り訂正と rateless 符号

主流は RS と、RS + 畳み込み符号。rateless 系には Smooth Codes (2012)、SoftLight (2016)、FOCUS (2016)、CCRCode (2025) がある。 RaptorQ で実測スループットを報告した査読論文は見つからなかった。 学習ベース (2019〜) の主眼は、人の目に見えないことと崩れにくさで、速さではない (1〜5 kbps)。

Vloom の位置づけ

言えること

  • 市販スマホのリアルタイム受信で、ファイルを最後まで転送した実測値が 1.1〜1.7 Mbps。 調べた範囲の学術報告 (スマホ受信、リアルタイム) より上。「調べた範囲で」と限定し、定義・端末・距離を添える
  • 条件を明記した繰り返し計測であること。競合の多くは「最良 1 回」か理論値
  • 同じ Rust コアを WASM・ネイティブ・Python で共有し、Web・Android・Windows で実装が分かれていない
  • OLED 送信と LCD 送信を同じ受信端末で比べた実測と、そこから得た知見 (60Hz では 30fps が上限、律速は受信の処理枚数)
  • RaptorQ + ブロック単位の部分回収の組み合わせで実測した例として (「RaptorQ で」と限定する)
  • MIT ライセンス (Decimen は AGPL に移った)

負けている・重なっている点

  • 速度: Decimen 418 KB/s、LIZARD 3.8 MB/s (いずれも自己申告)
  • 「輝度のみ」は LIZARD と FOCUS、「QR を使わない独自コード」は cimbar と LIZARD と重なる
  • RaptorQ の採用は RaptorQR と cuttldrop と重なる
  • iPhone での受信を前面に出していない。競合はブラウザでの iPhone 受信を前提にしている
  • 先行研究との差のかなりの部分は、端末世代 (センサ・ISP・CPU) の進歩による可能性がある
書かないほうがいい表現
  • 「世界最速」「最速クラス」: LIZARD・Decimen が上の値を公表している
  • 「ネットワークなしで光だけで転送する初めてのツール」: TXQR (2018) 以降、先行例が多数ある
  • 「fountain / rateless 符号を初めて使った」: Smooth Codes 2012、SoftLight 2016、FOCUS 2016 が先
  • 「部分回収・ブロック単位の誤り処理が新しい」: RDCode 2014、FOCUS 2016 が先
  • 「ローリングシャッターの混ざりへの対処が新しい」: LightSync 2013 以降、多数ある
  • 定義の違う数値 (PixNet の換算値、ChromaCode の raw 値など) を、断りなく並べること
公開時に先行事例として挙げておくもの: libcimbar、TXQR、Decimen、BC-UR (アニメ QR + fountain の業界標準)、FOCUS (学術で最も近い設計)。 RaptorQ を使う例として RaptorQR と cuttldrop。
